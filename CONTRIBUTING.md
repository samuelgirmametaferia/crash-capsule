# Contributing

## Getting set up

```bash
rustup show                 # installs the pinned toolchain from rust-toolchain.toml
cargo test --workspace
pre-commit install
```

## Before you push

```bash
cargo fmt --all
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace
cargo run -p cc-vectors     # regenerate the corpus; it must produce no diff in CI
```

## Things that will get a pull request rejected

- **Adding a field without a privacy class.** Every field in
  `specification/registry.toml` carries a minimum class and a justification. There is no
  default.
- **Lowering a privacy class** without a `schema_major` bump and new test vectors.
- **Changing the encoder, the registry or the fingerprints without regenerating the corpus.**
  The committed vectors are the contract with other implementations; a byte moving must be
  visible in the diff.
- **Hand-editing anything under `specification/test-vectors/` or
  `specification/privacy-registry.md`.** They are generated by `cargo run -p cc-vectors`.
- **`unsafe`.** It is `forbid`den workspace-wide.
- **Fingerprinting a boot-local value** — addresses, ASLR bases, PIDs, timestamps, CPU numbers.
- **Making fuzzy similarity authoritative.** It may suggest a merge; it may never perform one.

## Schema changes

| Change | Version impact | Also required |
| --- | --- | --- |
| New optional field, profile, evidence kind, category | `schema_minor` | Regenerate corpus |
| New critical feature bit | `schema_minor`, breaking for old readers | ADR explaining why the capsule is uninterpretable without it |
| Key renumbering, type change, class lowering | `schema_major` | New vectors, migration note |

## Architecture decisions

Anything that constrains future work — a wire format choice, a transport, a crypto primitive —
gets an ADR in `docs/adr/`, copied from `docs/adr/0000-template.md`. Record the alternatives you
rejected and why; that is the part that is useful in two years.

## Commit and review conventions

- Keep changes focused; a schema change and a transport change are two pull requests.
- Tests come with the change, not after it. In particular, a privacy rule without a test that
  demonstrates the violation being rejected is not implemented.
